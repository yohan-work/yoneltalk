  ## 가장 먼저 수정할 부분

  ### 1. 화면에 보이는 대화와 실제 답장 대상

  이 같은가?

  현재 내 담당 큐로 전환했을 때 선택된 대화

  가 큐에 없다면 화면은 첫 번째 대화를 대신

  보여 줍니다. 하지만

  state.selectedConversationId는 이전 값을

  유지합니다.

  그 결과 화면에는 Maya의 대화가 보이는데 답

  장은 Noah의 대화에 저장되는 상황이 발생할

  수 있습니다.

  근거:

  - 표시할 대화를 임시로 선택: src/app.js:24

  - 메시지를 저장할 때는 기존 상태 ID 사용:

    src/app.js:86

  수정 방향:

  - 큐 변경 시 유효한 첫 번째 Conversation

    ID를 상태에 저장합니다.

  - 답장 전에도 현재 Conversation이 선택된

    큐에 존재하는지 검증합니다.

  - 이 문제는 잘못된 고객에게 답장을 보내는

    오류이므로 최우선으로 수정해야 합니다.

  ### 2. 고객이 입력한 정보가 실제 문의 데이

  터가 되는가?

  현재 문의 폼의 값은 화면에서 수정할 수 있

  지만 제출 시 실제 입력값을 읽지 않습니다.

  submitRequest()가 제품, 리전, 오류 코드와

  메시지를 고정값으로 생성합니다.

  근거:

  - 입력 화면: src/app.js:18

  - 고정값으로 Conversation 생성: src/

    app.js:78

  소크라틱 질문은 다음과 같습니다.

  &gt; 고객이 다른 오류 코드와 내용을 입력해도

  &gt; 모든 문의가 EU-West 502로 생성된다면, 기

  &gt; 술정보 입력폼을 구현한 목적이 달성되는

  &gt; 가?

  수정 방향:

  - 폼 상태를 별도로 관리합니다.

  - 제품, 환경, 리전, 버전, 오류 코드,

    Request ID, 영향도, 재현 절차를 실제 제

    출 데이터에 반영합니다.

  - 필수값 검증과 오류 안내를 추가합니다.

  - 문의 유형 선택 단계를 복원해 기술 문의가

    아닌 경우 다른 필드를 보여 줍니다.

  ## 제품 경험을 더 디테일하게 만들 부분

  ### 3. 고객과 상담원이 동일한 사실을 보고

  있는가?

  현재 고객 Home은 “모든 시스템 정상”이라고

  표시하지만 데이터에는 Investigating 상태의

  Incident가 존재합니다. 고객 대화에서도 연

  결된 Incident가 표시되지 않습니다.

  근거:

  - 고정된 정상 상태 안내: src/app.js:20

  - 실제 조사 중 Incident: src/data.js:27

  수정 방향:

  - Home 서비스 상태를 Incident 데이터에서

    계산합니다.

  - 고객 대화에 연결된 Incident 제목, 상태,

    최신 업데이트를 표시합니다.

  - Incident가 해결되면 배너 상태도 자동으로

    변경합니다.

  - 운영자와 고객이 같은 장애 상태를 보도록

    하나의 데이터 원천을 사용합니다.

  ### 4. 고객 대화에서 누가 보낸 메시지인지

  구분되는가?

  고객 대화 화면은 내부 메모를 제외하지만,

  상담원 답장도 모두 고객 말풍선 스타일로 출

  력합니다.

  근거: src/app.js:19

  수정 방향:

  - customer, agent, system 메시지 유형별 렌

    더링을 분리합니다.

  - 내부 메모는 지금처럼 고객 화면에서 완전

    히 제외합니다.

  - Case 상태 변경이나 Incident 연결은

    system event로 보여 주는 방안이 좋습니

    다.

  ### 5. 지원 담당자가 Inbox에서 문제를 판단

  할 정보가 충분한가?

  현재 Context Panel에는 조직, 플랜, 제품,

  리전만 있습니다. RelayDesk의 차별점으로 정

  의한 환경, 버전, 오류 코드, Request ID, 고

  객 영향도가 Inbox에는 빠져 있습니다.

  근거: src/app.js:34

  수정 방향:

  - 기술 컨텍스트를 별도 섹션으로 분리합니

    다.

  - 환경, 버전, 오류 코드, Request ID, 영향

    도까지 표시합니다.

  - 중요한 값은 복사 버튼을 제공합니다.

  - 최근 배포와 서비스 상태는 샘플 데이터라

    도 함께 보여 줍니다.

  Case 상세에만 기술정보가 있고 Inbox에는 부

  족하면 상담원이 Case로 이동해야만 초기 판

  단할 수 있으므로 제품 목표와 어긋납니다.
